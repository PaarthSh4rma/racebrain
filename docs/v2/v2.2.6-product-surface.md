# V2.2.6 Product surface rehabilitation

## Objective

V2.2.6 makes the public RaceBrain product match the strongest implemented system. The root route no longer renders the legacy glassmorphism application, Race Engineer AI controls or competing replay panel. It is a compact technical entrance to two deliberately distinct tools: the deterministic Historical Model Workbench and the stochastic Scenario Simulation Lab.

## Public route architecture

```text
/
├── RaceBrain product entrance
├── capability status
└── links to the two supported product surfaces

/workbench
└── cutoff-safe Historical Model Workbench (primary V2 product)

/simulation
└── experimental Scenario Simulation Lab (legacy engine, rehabilitated UI)

unknown route
└── bounded not-found surface
```

The application keeps a lightweight pathname switch and a shared product header rather than adding a routing dependency. `frontend/vercel.json` continues to rewrite application paths to the Vite entry point while preserving the API proxy first, so all three routes support direct navigation and hard refresh.

## Historical modelling versus scenario simulation

The workbench reconstructs a canonical historical `RaceState` at an explicit cutoff and evaluates deterministic V2.2 pace and tyre evidence with no hindsight, typed `DataQuality`, provenance and robustness diagnostics. It is the serious primary RaceBrain product.

The simulation lab generates one-stop and two-stop candidates, deterministically pre-ranks them, retains a bounded top set, and compares those candidates across Monte Carlo perturbations. It samples base lap time, pit loss, track degradation and safety-car timing with shared scenario conditions plus candidate-specific execution noise. It does not consume historical `RaceState` and is not a V2 strategy decision engine.

## Monte Carlo terminology

The legacy backend calls candidate-comparison frequency `win_probability` / `win_percentage`, but it models which generated candidate is fastest within each sampled counterfactual—not whether a car wins a real race. The public UI therefore uses:

- **Scenario preference** and **Fastest in sampled scenarios** for the comparison frequency.
- **Average simulated race time** and **Scenario spread** for sampled timing output.
- **Generated strategies**, **Candidates evaluated** and **Runs per strategy** for experiment size.
- **Top-two preference gap** for the legacy `win_gap_to_second` field.

The backend `confidence` label is a simple threshold over that preference gap. It is validated for compatibility but hidden from the public UI; no high/medium/low model-confidence claim is made. The backend recommendation prose is also not rendered because it contains the same legacy confidence framing.

## Simulation lab architecture

`SimulationLabPage` owns track selection, bounded input state, optional seed, loading/error states and the single `/monte-carlo/generate` operation. `SimulationResults` presents experiment context, the best-ranked candidate, a dense ranking, returned safety-car/track assumptions and explicit limitations. The page calls only `/tracks` and `/monte-carlo/generate` during normal use.

The optional integer seed is sent through the existing backend field and the returned seed is shown, allowing a sampled run to be reproduced. The accepted engine configuration remains unchanged: `0.35 s` lap-time variance, `1.5 s` pit-loss variance, the track profile's degradation multiplier and safety-car probability, and at most ten deterministically pre-ranked candidates.

## Runtime validation and failure states

Small composable guards validate track profiles, simulation metadata, candidate counts, unique strategy identities, stint compounds/laps, scenario preference values, average/best/worst timing, spread, safety-car fields and seed. The validator requires a non-empty ranked set, the first ranked identity to match `best_strategy`, and the returned candidate count to reconcile exactly.

Track catalogue failure, empty catalogue, backend simulation failure, malformed JSON, inconsistent results and empty ranking all produce explicit bounded states. No demonstration result, stale fallback or fabricated candidate is inserted.

## AI and replay public removal

Legacy frontend/backend AI, LLM and Race Engineer code remains in the repository to avoid unrelated subsystem deletion, but no public route imports, renders or invokes it. Missing OpenRouter credentials cannot affect `/`, `/workbench` or `/simulation`. Normal browser acceptance asserts that no `/ai/*` or `/race-engineer/*` request occurs.

The old `ReplayPanel` is no longer imported or reachable from the public product. Historical reconstruction, replay evidence and validation are represented by the V2 workbench. Legacy replay backend routes and components remain compatibility/internal code for later V2.5/V2.6 work, and normal public navigation makes no `/replay/*` call.

## V2.3 boundary

This milestone changes public routing, presentation, terminology and frontend validation only. It does not add competitor/traffic, dirty-air, undercut/overcut, pit-window, rejoin, V2 strategy/recommendation/trigger, new ML, LLM explanation or replay-validation semantics. V2.3 and V2.4 remain untouched.

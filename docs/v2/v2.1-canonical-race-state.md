# V2.1 canonical historical race state

V2.1 reconstructs a provider-independent, full-field `RaceState` from historical OpenF1 data. It is an adapter/application capability only: it adds no public API, model, recommendation, UI, deployment, or V1 runtime migration.

## Flow and request pattern

`HistoricalRaceStateRequest` contains an OpenF1 session key, focal driver number, and completed decision lap. The application makes ten broad requests: `sessions`, the matching `meetings` metadata, `drivers`, `laps`, `stints`, `intervals`, `position`, `pit`, `weather`, and `race_control`. It deliberately does not request telemetry, location traces, session results, final classifications, or championship data. Existing transport caching and retry behavior is reused; there are no per-driver calls.

Provider JSON is first parsed into tolerant OpenF1 DTOs. Before semantic mapping, every explicitly foreign `session_key` is removed from every session-scoped dataset and counted in application diagnostics. Unknown fields are ignored, empty strings become missing values, valid timestamps are normalized to UTC, and structurally invalid records are counted and discarded. Only then does the mapper construct strict `domain_v2` objects.

## Cutoff and field semantics

The cutoff is the focal decision lap's `date_start + lap_duration`. Both values must exist, the duration must be finite and positive, and the resulting timestamp must be representable in UTC. OpenF1 documents `date_start` as approximate, so this assumption is present in provenance and data-quality warnings. Reconstruction fails with `ReconstructionFailure` rather than falling back to lap-number-only state. The focal driver must be a session entry and its canonical competitor must be present in the result.

All timestamped input is bounded at or before that cutoff:

| OpenF1 evidence | Canonical field | Rule |
|---|---|---|
| driver entry | field membership, name | safely associated session entries only |
| timed lap | `current_lap`, `recent_laps` | latest proven completed lap; last 10 retained |
| position | `position` | latest usable positive whole position at/before cutoff |
| interval | `gap_ahead`, `gap_to_leader` | latest usable dated gap; seconds or `+N LAP(S)` |
| stint | `tyre` | latest `lap_start` no later than current completed lap |
| pit | timestamped evidence and diagnostics | de-duplicated pit-lane passages; no stop count inferred |
| weather | `weather` | latest valid dated sample |
| race control | `track_status` | latest event establishing a supported state |

`current_lap` is a historical knowledge claim: the latest lap proven completed, not necessarily the lap currently being driven by the transponder. Competitors can therefore have different current laps at the same cutoff. `gap_behind` and `in_pit` remain missing because the selected feeds do not directly establish temporally aligned following gaps or exact pit occupancy. A null leader gap remains null.

Stints have no observation timestamp. Applicability uses only a valid bounded `lap_start`; a future `lap_end` is ignored. Tyre age is `tyre_age_at_start + current_lap - lap_start + 1`. Negative provider or reconstructed ages are rejected rather than clamped. Unknown compounds map to `UNKNOWN`, and physical tyre-set identity remains absent.

The OpenF1 pit feed establishes passage through the pit lane, not necessarily a stationary pit stop. De-duplicated bounded records may contribute car timestamps and provenance and are counted in diagnostics, but `pit_stop_count` and `in_pit` remain `None`. Deprecated `pit_duration` is not used.

Humidity is validated as a finite upstream percentage in `[0, 100]` and divided by 100. Wind speed must be finite and non-negative and is already metres per second. Temperatures must be finite and fit canonical ranges; rainfall accepts only boolean or integer zero/one evidence. An invalid newest sample is skipped in favor of the latest earlier usable sample.

## Canonical identity

The namespace and canonicalizer are versioned as V1 and generate UUIDv5-based opaque IDs. Text is trimmed, internal whitespace collapsed, and lower-cased.

- Event natural key: `f1 | year | meeting_name | country_name | location | circuit_short_name` from the matching meeting metadata.
- Session natural key: canonical EventId identity plus session type and session name.
- Competitor natural key: canonical SessionId identity plus racing/driver number as the session entry.

`Event.name` is the semantic provider `meeting_name`; no race name is fabricated. Sponsor-sensitive `meeting_official_name`, `circuit_key`, OpenF1 `meeting_key`, and `session_key` do not define identity. Provider keys and driver number are retained only as external metadata. `Event.circuit_id`, `driver_id`, and `tyre_set_id` remain absent because V2.1 has no approved provider-independent natural keys for those concepts.

## Track status, quality, and provenance

Track status is a conservative chronological global reducer. Driver- and sector-scoped flags and pit-lane/pit-exit messages are ignored. Explicit global red or session suspension establishes `RED`; deployment establishes `VSC` or `SAFETY_CAR`; only Track-scoped yellow establishes `YELLOW`; and only Track-scoped green or exact global `SESSION STARTED` establishes `GREEN`. `VSC ENDING` and `SAFETY CAR IN THIS LAP` do not end their states. Equal-timestamp conflicts use `RED > SAFETY_CAR > VSC > YELLOW > GREEN`. The final establishing evidence supplies `observed_at`.

Quality completeness is intentionally `None`; no artificial percentage is claimed. `GOOD` requires all defined per-car evidence or all field-level evidence. Missing usable lap, position, interval, tyre, weather, or control state degrades quality. Competitors with no timestamped observation are excluded rather than assigned a fabricated `observed_at`. Transport-boundary counts for malformed, untimed, duplicate, future, and foreign-session records remain deterministic application diagnostics so adding information outside the cutoff cannot mutate canonical state quality. The approximate-cutoff assumption and evidence-affecting omissions remain canonical warnings.

Race and car provenance names OpenF1, retains external session/driver metadata, preserves source observation times, and records conversions and assumptions. Raw payloads are not embedded in the domain. Provider-specific record counts and cache hits live in the application-layer diagnostics wrapper.

## No-hindsight proof and limitations

Fixture tests pair identical histories with aggressively different future laps, positions, intervals, stints, weather, pits, and race-control events and require identical canonical `RaceState` values. A second pairing contaminates every session-scoped dataset with explicitly foreign records and requires the same equality while diagnostics count the rejected records. Separate tests allow state to advance when the requested decision lap moves forward. Tests also cover latest-usable fallbacks, non-finite numbers, out-of-order/duplicate input, lapped gaps, mixed competitor laps, global control scope, future stint endpoints, pit-lane semantics, focal presence, meeting identity stability, and the ten-call provider pattern.

OpenF1's lap start is approximate, stints are untimestamped aggregates, interval feeds for competitors are independently timestamped, and historical feeds can be sparse or malformed. V2.1 exposes those limitations rather than inventing precision. Pace/degradation models, predictions, strategy recommendations, public V2 routes, frontend integration, and replacement of V1 replay are explicit non-goals.

Provider field semantics were checked against the [official OpenF1 API documentation](https://openf1.org/docs/).

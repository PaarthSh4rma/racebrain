# V2.1 canonical historical race state

V2.1 reconstructs a provider-independent, full-field `RaceState` from historical OpenF1 data. It is an adapter/application capability only: it adds no public API, model, recommendation, UI, deployment, or V1 runtime migration.

## Flow and request pattern

`HistoricalRaceStateRequest` contains an OpenF1 session key, focal driver number, and completed decision lap. The application makes one session-level request for each of `sessions`, `drivers`, `laps`, `stints`, `intervals`, `position`, `pit`, `weather`, and `race_control`. It deliberately does not request telemetry, location, session results, final classifications, or championship data. Existing transport caching and retry behavior is reused; there are no per-driver calls.

Provider JSON is first parsed into tolerant OpenF1 DTOs. Unknown fields are ignored, empty strings become missing values, valid timestamps are normalized to UTC, and structurally invalid records are counted and discarded. Only then does the mapper construct strict `domain_v2` objects.

## Cutoff and field semantics

The cutoff is the focal decision lap's `date_start + lap_duration`. Both values must exist, the duration must be positive, and the resulting timestamp is UTC. OpenF1 documents `date_start` as approximate, so this assumption is present in provenance and data-quality warnings. Reconstruction fails with `ReconstructionFailure` rather than falling back to lap-number-only state.

All timestamped input is bounded at or before that cutoff:

| OpenF1 evidence | Canonical field | Rule |
|---|---|---|
| driver entry | field membership, name | safely associated session entries only |
| timed lap | `current_lap`, `recent_laps` | latest proven completed lap; last 10 retained |
| position | `position` | latest dated record at/before cutoff |
| interval | `gap_ahead`, `gap_to_leader` | latest dated record; seconds or `+N LAP(S)` |
| stint | `tyre` | latest `lap_start` no later than current completed lap |
| pit | `pit_stop_count` | count of dated events at/before cutoff |
| weather | `weather` | latest valid dated sample |
| race control | `track_status` | latest event establishing a supported state |

`current_lap` is a historical knowledge claim: the latest lap proven completed, not necessarily the lap currently being driven by the transponder. Competitors can therefore have different current laps at the same cutoff. `gap_behind` and `in_pit` remain missing because the selected feeds do not directly establish temporally aligned following gaps or exact pit occupancy. A null leader gap remains null.

Stints have no observation timestamp. Applicability uses only `lap_start`; a future `lap_end` is ignored. Tyre age is `tyre_age_at_start + current_lap - lap_start + 1`. Unknown compounds map to `UNKNOWN`, and physical tyre-set identity remains absent. Pit mapping uses `date`, `lane_duration`, and `stop_duration` only; deprecated `pit_duration` is not used.

Humidity is validated as an upstream percentage in `[0, 100]` and divided by 100. Wind speed is already metres per second. Invalid humidity makes that sample unusable rather than silently clamping it.

## Canonical identity

The namespace and canonicalizer are versioned as V1 and generate UUIDv5-based opaque IDs. Text is trimmed, internal whitespace collapsed, and lower-cased.

- Event natural key: `f1 | year | country/location/circuit place | race event name`.
- Session natural key: canonical EventId identity plus session type and session name.
- Competitor natural key: canonical SessionId identity plus racing/driver number as the session entry.

OpenF1 `meeting_key`, `session_key`, and driver number are retained as external metadata; the provider session and meeting keys never define semantic IDs. `driver_id` and `tyre_set_id` remain absent because V2.1 has no defensible persistent-driver or physical-set natural key.

## Track status, quality, and provenance

Track status uses explicit, conservative rules: red flags establish `RED`; virtual-safety-car deployment establishes `VSC`; safety-car deployment establishes `SAFETY_CAR`; yellow flags establish `YELLOW`; green flags, an exact `SESSION STARTED` session-status event, and explicit VSC/safety-car ending messages establish `GREEN`. Unrecognized messages establish no state. The establishing event timestamp is retained.

Quality completeness is intentionally `None`; no artificial percentage is claimed. `GOOD` requires all defined per-car evidence or all field-level evidence. Missing lap, position, interval, tyre, weather, or control state degrades quality. Excluded competitors, malformed or untimed input, deterministic duplicate resolution, future-record exclusion, and approximate lap-start cutoff derivation are reported as warnings. Competitors with no timestamped observation are excluded rather than assigned a fabricated `observed_at`.

Race and car provenance names OpenF1, retains external session/driver metadata, preserves source observation times, and records conversions and assumptions. Raw payloads are not embedded in the domain. Provider-specific record counts and cache hits live in the application-layer diagnostics wrapper.

## No-hindsight proof and limitations

Fixture tests pair identical histories with aggressively different future laps, positions, intervals, stints, weather, pits, and race-control events and require identical canonical `RaceState` values. Separate tests allow state to advance when the requested decision lap moves forward. Tests also cover out-of-order/duplicate input, missing and malformed timestamps, lapped gaps, mixed competitor laps, weather bounds, future stint endpoints, future pits, excluded competitors, identity stability, and the bounded provider-call pattern.

OpenF1's lap start is approximate, stints are untimestamped aggregates, interval feeds for competitors are independently timestamped, and historical feeds can be sparse or malformed. V2.1 exposes those limitations rather than inventing precision. Pace/degradation models, predictions, strategy recommendations, public V2 routes, frontend integration, and replacement of V1 replay are explicit non-goals.

Provider field semantics were checked against the [official OpenF1 API documentation](https://openf1.org/docs/).

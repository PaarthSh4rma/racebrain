# V2.1.5 historical RaceState workbench

V2.1.5 is the first operator-facing presentation of canonical historical `RaceState`. It adds discovery, API serialization, and inspection UI without changing V2.1 domain semantics or adding modelling, prediction, recommendations, AI, storage, or background polling.

## Architecture and API

The runtime path remains:

`OpenF1 → tolerant DTOs → cutoff-safe V2.1 normalization → canonical RaceState → explicit API response → workbench`

The thin read-only router exposes:

- `GET /v2/historical/sessions?year=2024`
- `GET /v2/historical/sessions/{session_key}/drivers`
- `GET /v2/historical/sessions/{session_key}/drivers/{driver_number}/decision-laps`
- `POST /v2/historical/race-state`

Discovery uses only provider session, meeting, driver, and valid completed-lap evidence. Reconstruction delegates to `reconstruct_historical_race_state`; API handlers contain no canonical mapping logic. Invalid input is `422`, missing focal entries are `404`, unusable or unavailable OpenF1 data is `502`, and unexpected failures return sanitized `500` responses.

## Workbench behavior

`/workbench` uses the existing React/Vite entry point and local component state. No routing or state-management dependency was added. Season, event, driver, and lap changes reset incompatible downstream state. Abort signals prevent superseded discovery or reconstruction requests from overwriting newer selections.

The main surface is a position-sorted full-field table showing completed lap, dimension-preserving gaps, tyre state, age, and per-car quality. P1 `gap_ahead` is unavailable while an explicitly reported zero leader gap renders as `0.0s`; lapped gaps render as `+N LAP(S)`. Missing canonical fields render as an em dash, never zero or false. Nullable pit-stop and in-pit fields are omitted from car detail rather than invented.

The context strip shows event, session, decision lap, UTC cutoff, global track state, and latest bounded weather. Row selection updates a detail pane with canonical observations, missing fields, warnings, and collapsible human-readable provenance. Global quality presents degradation as inspectable uncertainty and includes the known approximate OpenF1 lap-start assumption.

Loading, empty, malformed-response, no-state, and upstream-failure states remain explicit. Dense tables scroll intentionally at narrow widths while controls and details stack.

## Limitations and live smoke

The UI displays historical evidence; it does not estimate pace, tyre degradation, competitors, rejoin position, pit loss, or strategy. OpenF1 cold starts can take several seconds. Stints remain untimestamped aggregates, pit-lane passages do not establish pit-stop counts, gaps can be missing, and lap start timestamps are approximate.

Manual API smoke commands can use the Monaco 2024 session `9523`, driver `16`, lap `10`, and Spain 2024 session `9539`, driver `1`, lap `20`. Both were exercised during implementation through the public endpoint and reproduced the accepted V2.1 field characteristics.

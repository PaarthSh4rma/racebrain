# V2.2.5 Historical model analysis workbench

## Objective

V2.2.5 turns the historical state viewer into an operator-facing modelling workbench. At one historical decision point it presents the canonical cutoff-safe race state, representative clean-lap pace, empirical included-lap spread, observed tyre-age pace slope, deterministic leave-one-out (LOO) sensitivity, exact accepted and excluded evidence, `DataQuality`, provenance and model identity. It does not make a strategy recommendation.

## Architecture

```text
POST /v2/historical/analysis
          |
          v
analyze_historical_decision_point
          |
          | exactly once
          v
build_historical_pace_context
          |
          +-- canonical RaceState + reconstruction/modelling diagnostics
          +-- full-field representative pace + empirical robustness
          `-- full-field tyre-age slope + LOO robustness
                              |
                              v
                HistoricalAnalysisResponse
                              |
                              v
                 React operator workbench
```

The application service owns orchestration; the API handler only validates the request, calls the service and serializes its typed result. Provider access ends at context construction. Both full-field model families consume the same immutable `PaceEstimationContext`, so one operator action performs one context build rather than one fetch path per model or competitor.

## Historical analysis request path

`POST /v2/historical/analysis` reuses the existing decision-point request:

```json
{
  "session_key": 9539,
  "driver_number": 4,
  "decision_lap": 50
}
```

The response carries `race_state`, reconstruction and modelling diagnostics, full-field `pace` robustness, full-field `tyre_age_slope` robustness and exact per-competitor evidence audits. Canonical competitor IDs join every section. Contract validation requires the race-state and model cutoffs to match and requires each canonical competitor to have one pace result, one tyre result and one evidence record. Model names, versions, configuration hashes, evidence windows, limitations, provenance, `DataQuality` and typed unavailable reasons remain inspectable. No raw OpenF1 DTO is public. `POST /v2/historical/race-state` remains supported.

OpenF1 failures are returned by the API as a bounded `502` with the existing sanitized message. Malformed evidence fails safely; it does not create a partial or fabricated model result.

## Frozen model semantics

Representative pace remains the median of eligible observations in the trailing eight-lap-number window, with at least three clean laps, all factual exclusions and configured `WEATHER_TRANSITION` exclusion. It has no fuel, tyre, track-evolution or traffic correction.

P10, p50 and p90 describe the empirical distribution of the exact included lap times using deterministic linear interpolation; p50 equals the accepted point median. The workbench calls p10-p90 the **empirical included-lap spread**. It is not a confidence, prediction or probability interval.

Tyre-age pace slope remains closed-form OLS over exactly the latest canonical bounded stint, requiring one identified compound, at least five clean observations and a four-lap age span. It never falls back to an older stint or pools stints. Negative values are valid. The value is an observed lap-time association in `s/lap/lap`, not causal physical tyre degradation; fuel load, track evolution, traffic and driver management remain unresolved.

For every available slope, deterministic LOO diagnostics omit each accepted observation once and refit the same OLS model. `sign_stable` is true only if every refit retains the nominal sign under the explicit `1e-9 s/lap/lap` zero tolerance. The sensitivity envelope contains the nominal and all LOO slopes and is non-probabilistic. Stable sign is not confidence, certainty or magnitude accuracy.

## Unavailable results, quality and provenance

Unavailable is a typed result, not a blank cell. The UI gives the original reason, candidate/included counts, latest-stint compound and stint where known, and states that no earlier stint was substituted. Full-field partial availability is normal.

`DataQuality` is shown independently for each result and retains model-relevant limitations from accepted evidence. Provenance and diagnostics remain bounded by the historical cutoff; a later retrieval timestamp is permitted but a future source-observation timestamp is rejected. The UI never improves quality, recomputes a model value or infers meaning from provenance prose.

## Frontend design

The workbench performs one analysis request and maintains one shared selected-competitor state across the full-field model comparison and canonical race-state table. The selected-car summary prioritizes representative pace, empirical spread and tyre-age slope. A compact comparison table exposes the field without presenting it as normalized intrinsic car performance. Expandable diagnostics expose candidate, included and excluded laps with reasons, residual statistics, evidence windows, LOO refits, versions, hashes and limitations without overwhelming the default view.

Runtime validation is composed from small guards for race state, model identities, point fits, robustness diagnostics, quality, provenance and evidence audits. It reconciles cutoffs and competitor IDs before the response reaches React. A malformed response produces a distinct safe error state. Provider failure retains the operator's selections and never switches to fixture data.

## Historical validation harness

Run the same production application and model path from `backend`:

```bash
.venv/bin/python -m scripts.v2_2_historical_validation SESSION_KEY DRIVER_NUMBER DECISION_LAP
```

The command prints deterministic JSON containing event/session, focal competitor, cutoff, pace and empirical quantiles, sample counts, tyre result or unavailable reason, sign stability, LOO envelope, quality and model hashes. A temporary provider failure produces a structured error and non-zero exit status.

## V2.3 boundary

V2.2.5 adds presentation and orchestration only around the accepted V2.2 models. It does not add competitor/traffic loss, dirty air, undercut/overcut, pit loss, rejoin, strategy simulation, recommendation/trigger engines, LLM explanation, probability, tyre-life prediction, fuel correction, track-evolution correction, causal degradation or any new model. V2.3 and V2.4 remain untouched.
